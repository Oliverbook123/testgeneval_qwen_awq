# Qwen 官方源码对照与最小修复验证

时间：2026-11-07 10:23（北京时间）。

参照仓库：facebookresearch/testgeneval；联网核对官方 main 与本地基础提交均为 `67ea3ff37643b3078413d6e4fadaae00ce8d9e5d`。没有替换整个仓库或覆盖既有实验结果。

当前全部工作区差异包含历史修改：46 个已跟踪改动文件中，32 个是此前国内下载源、依赖与镜像构建相关 Docker 文件。本轮修复不等同于这 46 个文件全部重写。官方环境配置使用 vLLM 0.6.0，当前使用 0.10.2；官方模型配置不含 Qwen，因此需要额外适配。此前 Qwen 未接聊天模板属于本地接入遗漏，不应归咎于官方流程。

本轮生产代码集中在五处：

| 文件 | 修改目的 |
|---|---|
| inference/configs/qwen2_prompt.py（新增） | 仿官方 Llama3 适配器应用 Qwen 模板，截断时保留角色和任务指令 |
| inference/huggingface/run_huggingface.py | 接入 Qwen 适配器与模型专用截断 |
| inference/huggingface/huggingface_utils.py | 保留必要 vLLM 接口兼容，仅在 vLLM 路径记录原始输出及停止元数据 |
| swebench_docker/swebench_utils.py | 修正分 setting 日志匹配，保留指标算法 |
| swebench_docker/context_manager.py | 仅为 Sphinx 3.2/3.5 的 tox 环境补 setuptools<82 约束 |

已收敛不必要重构：生成文件恢复官方 HF/vLLM 双分支；HF 分支及 TokenizedDataset 与官方 AST 一致。该文件相对官方的差异为 48 行新增、5 行删除，其中也包含此前已有的 vLLM 兼容修复。额外的通用覆盖率命令去重已撤销。

官方 InstructPrompt 文件保持逐字一致；Qwen 继续继承其严格代码围栏和函数提取规则，没有通过放宽输出要求提高分数。

验证结果：

- 50 项回归通过：29 项本轮测试、14 项续跑、3 项 vLLM 接口、4 项流水线测试。
- 最终最小补丁下，真实 Qwen GPU 合成样本四种设置生成 16 条候选，16 条均严格抽取成功且 Python 语法有效。这是功能验证，不是正式 benchmark 分数或测试断言通过率。
- 原始输出在整批后处理之前保存；首候选后处理抛错时，同批其他候选原文也不丢失。
- 两张既有 Sphinx 镜像 fresh tox 环境均能导入 pkg_resources 和测试插件，分别收集 8、19 个测试；未重建或删除镜像。
- 修复后的辅助报告识别 160 个样本日志和 2 个变异超时；旧预测与旧报告文件校验值保持不变。

正式重新评测应使用新 results_dir，避免旧预测缓存被当作新适配器的生成结果。旧 160 样本实验的数值不会因修改源代码自动更新。
